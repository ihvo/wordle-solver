A small policy that plays
Wordle perfectly.

Behavior cloning got a 1.04M-parameter network to 99.4%. Reinforcement learning then taught it the one move imitation couldn't — probing — and closed the gap to a perfect 100% across all 2,315 answers. A last round of imitation then folded the endgame rule into the weights, so it plays raw — no hand-coded rail. Here's the pipeline, stage by stage.

Stage 0 · The environment

The game, as an environment

Guess a hidden 5-letter word; each guess returns a per-letter color signal. That signal is the entire observation — so the task is sequential decision-making under partial information, and good play is about extracting the most from each response.

The feedback function. Type a guess and a hidden answer to see the coloring Wordle returns:

Green = correct letter and position. Yellow = present, wrong position. Gray = absent (with correct multiplicity — a repeated letter only earns as many marks as the answer holds).

This function is cheap to evaluate for every word pair, so we precompute the full 2315×2315 pattern matrix once. Every stage below is built on it.

Stage 1 · The teacher

An entropy solver as the baseline

Before any learning, the baseline is a classic information-theoretic solver. Each turn it scores every guess by the expected information gain over the remaining answers and plays the maximizer — the guess whose feedback splits the possibilities most evenly.

The candidate set. At any point, only some answers are still consistent with the feedback so far — call that set the candidates. A guess's value is the Shannon entropy of the feedback partition it induces over the candidates: more, smaller groups = more bits = a faster-shrinking set.

Stage 2 · Behavior cloning

Cloning the solver

First learning step: train a network to imitate the solver, supervised on (state → best guess) pairs from teacher self-play. That's behavior cloning. The architecture turned out to matter far less than the state representation we fed it.

The representation that failed. Feed the raw move history — past guesses and feedback as tokens — and predict the next word. The net learned almost nothing: it sat at the random-consistent baseline.

The candidate set is the sufficient statistic. Don't make the net re-derive state from the history — hand it a summary of the candidates. The one we used: per-position letter frequencies (5×26) plus letter-presence frequencies (26), a 156-d vector. Below are those per-position marginals over the live candidate set — the features the policy actually consumes.

Bar height = that letter's frequency in that position across the surviving candidates. The policy reads these marginals and learns to rank guesses from them.

Stage 4 · The structural gap

The trap: masked play has a ceiling

The cloned policy only ever guesses candidates. That's safe, but it caps the win rate: in clusters of near-identical words, it peels them off one per turn and can exhaust the budget.

A classic trap. The answer is one of these look-alikes and you have a limited number of guesses left:

This is probing. Play a non-candidate purely for information — its feedback partitions the tied set in a single move. Greedy entropy over the full guess pool does this for free; masking the policy to candidates makes it structurally impossible. That masking ceiling is ~99.7% — exactly where cloning tops out.

Probing can't be supervised in.

We relabeled the BC targets with the full-pool teacher's probes and retrained at both model sizes. Every variant got worse. The reason is the crux of the whole project: a probe's value is a multi-step return — a setup for a later guess — and that can't be expressed as a per-state cross-entropy label. Hold that thought for Stage 5.

One free win first: turn 1 is a single deterministic state, so we fix it to a strong opener (SLATE), forced at inference rather than learned. That alone moved the average 3.62 → 3.55 at zero parameter cost.

Stage 5 · Reinforcement learning → 100%

Optimize the objective directly

If a probe can't be a supervised label, stop supervising and optimize the objective. Let the policy self-play and reward it for the outcome — reinforcement learning. It discovers probing on its own, and closes the last 0.3% to a perfect score.

Why RL works where cloning didn't. A terminal win reward credits a probe through the multi-step return; a per-state label can't. Probing is a credit-assignment problem, not a labeling one — precisely why supervised relabeling failed in Stage 4.

The recipe

1

Terminal reward

R = solved ? (7−turns) : 0. Every win dominates every loss, so win-rate is the primary objective; fewer guesses scores higher, so the policy never probes gratuitously.

2

Teacher-seeded exploration

On hard traps, on-policy sampling rarely finds a winning probe. We inject the entropy teacher's trajectory into each GRPO group so the group-relative advantage is non-zero exactly where learning is needed.

3

Hybrid rail

When candidates ≤ guesses left, enumerating can't lose — so mask. Only lift the mask (probe) when stuck. Folding this into the rollout focuses every gradient on the probe decision itself.

4

KL anchor

A KL penalty to the frozen BC reference on normal states holds the rest of the policy in place while the stuck-state probes are reshaped.

The climb to 100%

Hybrid win rate vs. training updates. High-variance while exploring, then it locks the probes and saturates at a perfect score.

An instructive failure. An earlier run hit 99.9% hybrid but collapsed to 94.6% unmasked — gradient focused on stuck states had rotted normal play, and the rail hid it at eval. The KL anchor (step 4) fixed it. Lesson: monitor the off-objective metric, not just the one you select on.

Stage 6 · Folding in the rail

Internalizing the rail

The 100% from Stage 5 still leaned on the hybrid rail — an inference rule bolted on top of the net. Could the network learn the rule itself and play raw (pure argmax, no mask, no probe branch) at 100%? It can.

The blocker was the input, not the net. The rail's test is candidates ≤ guesses left. But the candidate features are normalized (fractions), so they throw away the candidate count — and the small net has no notion of the guess budget. You can't learn a rule whose inputs aren't in the observation. So we added two features: how many candidates remain, and how many guesses are left (156-d → 170-d).

Then imitate the expert — DAgger. The hybrid policy is already a perfect expert, so we train the net to copy its move at every state (now with the count/budget features) and play it raw. Each round, we roll the student out raw and re-label the states it actually visits — fixing its own mistakes. Three rounds closed the gap:

On the final net, raw == hybrid == 100%: switch the rail off and it plays identically and never loses. It probes on its own.

The honest part. We expected a learned threshold to stay fuzzy near C ≈ R and leave a few stubborn losses — a theorem (the rail) vs. a function approximator. It hit exactly zero. And plain imitation got there — the reinforcement-learning polish we'd planned wasn't needed once the decision was observable. Two caveats: the result is an empirical 0 over the closed set of 2,315 answers (complete for this net, not a proof), and this net keeps the opener forced — though the solver-free net below shows even that can be learned. The rail still ships as a free safety net (--safe); it's just no longer required.
Stage 7 · Writing the word

Generating, not choosing

Every policy so far is a classifier: it scores all 2,315 answer words and takes the argmax — a wrong "word" is impossible by construction. The next generation asks the opposite question: can the net write the guess letter-by-letter, with no vocabulary at all? It can then emit any of 26⁵ ≈ 12M strings — including non-words. Can it learn to stay valid and win?

Why this is hard. Drop the word head and decode 5 letters with a GRU. Two problems show up at once: validity — nothing stops it emitting birty; and exposure bias — behavior cloning teacher-forces the true previous letters, so the decoder never practises recovering from its own prefixes, then drifts off the word manifold at play time.

Three fixes, in order. Let it roll out under RL on its own outputs (it finally sees its own prefixes); then condition each letter step on the per-slot candidate marginals — the live letter frequencies among surviving answers, fed in through marg_proj, so it generates toward real in-set words (the big lever); then more RL with a valid-word bonus. No trie, no mask, no allowed-word list anywhere in the loop.

The honest part. "Generation can't do a closed vocab" was wrong — it was exposure bias plus missing conditioning, not the head. But there's a catch: the marginal conditioning that fixes validity also steers away from non-candidate words — and a probe is exactly a non-candidate word. So the same lever that solves validity suppresses probing, and the decoder caps right at the masked-play ceiling: the last ~0.5% (13 losses) are the genuine neighbour-traps, not non-words — the same wall every other policy hits, reached from the opposite direction. (An LM-prior pretrain and an explicit unlikelihood penalty both hurt; beam search rescued the weak model but was redundant once it was confident.) Research variant — the classifiers and the solver-free net remain the shipped policies.
Reference · Architectures

The models, side by side

Every component that appears across the stages, side by side: one exact solver, the small networks, the inference rule that wraps them, and the generative head. Here's what each looks like and what it does. The classifier models share the same encoding — a candidate-set summary and (optionally) a tokenized move history — and emit logits over the 2,315-word vocabulary; the solver-free net reads only the tokens, and the generative decoder writes the word letter-by-letter instead.

Entropy teacher baseline · 0 parameters

Not learned — exact information-theoretic search. From the candidate set it reads precomputed feedback patterns (the pattern matrix), forms each guess's feedback histogram over the candidates, and plays the maximum-entropy guess (greatest expected shrinkage of the set). 100% win, 3.50 avg. It's the teacher to imitate, the baseline to beat, and the exact candidate-tracking engine every policy below rides on.

Transformer policy behavior-cloned & RL · 1.04M params

Two input branches. (1) History: the move sequence is tokenized (token = letter×3 + color, ≤26 positions incl. a START), passed through learned token + positional embeddings and a 3-layer Transformer encoder (4 heads, FF 256); the START position is read out as a 128-d summary. (2) Candidate features: the 156-d candidate-set summary through a small MLP to 128-d. The two vectors are concatenated (256-d) and a linear head projects to per-word logits. Behavior cloning trains it on the teacher's moves; the RL stage fine-tunes these same weights on the terminal win reward — architecture unchanged, only the play-time rule differs (the hybrid rail, below).

Candidate-only MLP ablation · 0.34M params

The Stage-3 ablation: drop the history branch and the Transformer entirely. Just the 156-d candidate features → 156→128→128 MLP (GELU) → linear head over 2,315 words. About 90% of its 0.34M parameters live in that output head. It plays identically to the Transformer — direct evidence that the candidate set is the sufficient statistic and the policy is really just a ranker over it.

Hybrid rail RL inference policy · 0 parameters

Not a network — the deployment rule that wraps the RL policy. Turn 1 is forced to the fixed opener (SLATE). Otherwise: if candidates ≤ guesses left, mask the logits to candidates and take the best one (enumerating can't lose); if stuck (candidates outnumber the budget), lift the mask and let the net pick over the full pool — a probe. This rail is what lets the learned probing reach 100% while never risking an invalid endgame. Once the count/budget features are in the input, the network internalizes this rule and plays raw without it (policy_raw.pt, 100%) — so the rail is now an optional safety net (see Rail-free).

History-only net no solver, no rules · 0.5M params

The experiment from the Rail-free follow-up taken to its limit: drop the candidate features entirely and read only the move history. The catch is the readout — a single summary vector can't say which of 2,315 words are still consistent. So each word (embedded from its letters) is the query in a cross-attention over the encoded history (the keys/values), and is scored against its own attended context. That per-word × history interaction lets the net check its own candidacy. Played raw it reaches 100% from tokens alone — no candidate set ever computed for the policy. Getting there took three fixes: the cross-attention readout (→99.87%), a solver-free duplicate-letter feature (the brittle cases), and a raw-RL polish optimising the win objective (the last two losses).

It even learns its own opener. Turn 1 used to be hard-coded (one deterministic state a net under-trains on). But played in every RL game it gets the most gradient of any state — given the chance, the net commits to opening SLATE on its own (0.999 confidence) and still solves all 2,315. So this is a completely rule-free policy: tokens in, guess out — no candidate set, no rail, no forced opener.

Generative decoder next generation · 0.59M params

The next generation of the policy. Every model above is a classifier — it scores all 2,315 words and argmaxes. This one writes the guess letter-by-letter with no vocabulary at all: it can emit any of 26⁵ ≈ 12M strings, so nothing structurally stops it from outputting a non-word. The same shared front-end produces the state — token+positional embeddings (token = letter×3 + color, ≤26 positions), a 3-layer Transformer encoder (d=128, 4 heads, FF 256, ~397K params), and the 170-d candidate features through an MLP to 128-d — concatenated into a 256-d state z. The selection head is gone; in its place a small autoregressive decoder (~142K params).

The decoder head, step by step. state_proj (256→128) turns z into the GRU's initial hidden state. Then for each of the 5 slots a GRUCell(128→128) reads two things — the previous letter via Embedding(27→128) (26 letters + a START symbol) and the live per-slot candidate marginal via marg_proj (26→128, the conditioning lever) — and out (128→26) emits that slot's letter distribution. Greedy/sampled letters feed back in, so the word is built one symbol at a time.

Why it took work. Teacher-forced it hit only 33% win / 41% non-words (plausible fakes like birty) — classic exposure bias. Three fixes turned it around: RL on its own rollouts (the decoder sees its own prefixes → 71%), per-slot candidate conditioning (marg_proj feeds each step the live letter frequencies, so it generates toward real in-set words — the big lever), and more RL with a valid-word reward bonus. End state: 99.44% win, 0.08% non-words, avg 3.55 — a pure generative, no-constraint head competitive with the classifiers. (Beam search rescued the weak model, 35→45%, but was redundant once it was confident.) The catch: the conditioning that fixed validity also suppresses probing, so it caps near the masked ceiling — the last ~0.5% is the neighbour-traps, not non-words.
